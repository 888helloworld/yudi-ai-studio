
定时备份每天03:17以SYSTEM身份隐藏运行，补跑错过的任务，禁止重叠执行，运行日志在logs。完整备份成功后运行数据保留清理。磁盘不足时停止备份并保留旧快照，不宣称备份成功。后台超过36小时未备份时显示提示。

本机没有正式域名和异地存储，因此保持127.0.0.1本机使用；不启用会导致HTTP无法登录的Secure Cookie。没有异地副本，整机/整盘损坏仍可能丢失资料。以后将BACKUP_MIRROR_DIR指向独立磁盘或受控网络盘，脚本会复制并再次校验，密钥不在备份包内。

## 恢复步骤

1. 停止应用，保留当前数据库和uploads副本作为回退。
2. 对指定快照运行上面的--verify命令；校验失败禁止使用该快照。
3. 在空的恢复目录中放入快照data.db和uploads，使用项目相同版本运行依赖和服务。不要把旧的data.db-wal/data.db-shm混入恢复目录。
4. 单进程启动应用：普通未完成任务退款，画面工坊恢复或退款。检查用户数、余额、样例作品下载。
5. 确认后再切换正式数据目录。备份不包含.env，密钥由本机安全配置提供。

## 当前边界

- 新任务账本从本版本开始生效，不能仅凭旧流水自动判断历史无业务号扣费是否应退款。
- 任务恢复要求同一数据库只运行一个服务实例；多实例部署需要独立工作队列与租约。
- 不调用真实付费模型做自动化测试；采用隔离数据库和模拟上游，真实模型的画质/可用性不在自动测试保证范围内。
- 使用HTTP/浏览器下载事件只能统计下载发起，不能确认用户最终保存到硬盘。
- 自动支付保持关闭。启用前必须完成真实商户配置、回调验签、商户与订单金额/币种校验、重复通知测试、主动查单、退款与对账。
- 公网部署先运行生产检查，配置HTTPS域名、代理层数、Secure Cookie和独立备份。当前不替使用者虚构这些配置。
