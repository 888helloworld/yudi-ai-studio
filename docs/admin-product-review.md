# 管理后台产品评审 · 2026-09-06

目标：让管理员快速看清经营数据、查到问题用户和订单，减少积分误操作。

## 本次已落地

| 原问题 | 修改 |
| --- | --- |
| 九个统计卡片过高 | 桌面九列、窄屏五列、手机三列，字号与留白缩小 |
| 统计口径不明确、加载失败无提示 | 增加口径说明、刷新按钮、更新时间和失败提示；余额、支付充值与人工调整分别说明 |
| 退款、赠送、人工调整都被显示为消费 | 按真实流水类型显示；正负颜色与金额符号按实际增减判断 |
| 查账只能翻页 | 流水支持用户名/说明及类型组合查询；订单支持订单号/用户名及状态组合查询；可重置 |
| 搜索空结果无反馈 | 用户列表增加无匹配提示；订单请求失败可在页面重试 |
| 人工加分被误解为收款 | 改为“人工加积分”，明确不计入收入；提交期间禁用按钮；前后端拒绝非整数输入 |
| 运营页面表单布局松散 | 账单、上线检查和反馈表单统一间距、输入样式及移动布局 |

## 下一阶段优先级

| 优先级 | 建议 | 解决的问题 |
| --- | --- | --- |
| 已完成 | 用户详情整合余额、订单、流水、生成任务和创作记录，支持分页和刷新 | 可从用户列表或任务中心进入 |
| 已完成 | 任务中心支持状态/用户名/任务号筛选；展示原扣、退款、实耗和对应流水 | 合并两种任务存储并去重；旧流水未完全匹配时提示人工核对 |
| 高 | 所有人工积分操作统一成带余额预览和必填原因的表单，服务端引入操作幂等键 | 本次防连点只覆盖加积分表单，完整解决网络重试重复操作需要业务幂等 |
| 中 | 订单、流水增加日期筛选及按筛选结果导出 | 支持周期对账；导出需要控制数量和防止表格公式注入 |
| 中 | 反馈按待处理/已处理筛选，并显示待处理数量入口 | 降低漏处理概率 |
| 中 | 将重置密码、封禁和删除收入“更多操作” | 保留审计与二次确认，降低列表操作密度和误触 |

真实支付自动化、自动退款、多角色权限属于独立业务改造，需明确支付渠道及人员职责后实施。现有“确认到账”是人工核对后的操作，不应理解成支付平台自动核验。

## 验证

使用独立测试数据库启动服务；完成语法检查、数据库和 HTTP 冒烟测试，并补充查账筛选、分页及特殊关键词回归测试。浏览器检查桌面和手机布局、登录、加积分入口及查账查询。未改动线上数据库。

## 第二阶段验证

用户详情及任务中心使用独立数据库启动服务，完成桌面/手机浏览器检查。6 项数据库与 HTTP 回归测试通过，覆盖用户隔离、管理员权限、敏感字段排除、任务去重、旧退款流水匹配及分页。新页面时间统一为北京时间。任务中心提供排查和核对入口，不增加自动重试或补退款操作。
